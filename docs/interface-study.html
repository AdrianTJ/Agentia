Where it still fails

Three failure classes survive the reranker upgrade. All three share a root cause: the chunker splits tables mid-row, so the embedding never sees a complete record.

  1. Table fragmentation — 61% of remaining misses. Fix in the chunker, not the retriever.
  2. Acronym collisions — 22%. Needs a domain glossary at query-expansion time.
  3. Temporal drift — 17%. Documents lack effective-date metadata.

Reproducing this

The harness is deterministic given a fixed seed and a pinned index snapshot:

# pin the index, then run the sweep
uv run eval/harness.py \
  --index snapshots/2026-08-07.faiss \
  --reranker bge-reranker-v2-m3 \
  --pool 50 --seed 41 \
  --out out/eval-report.md

Results land in out/ as both Markdown and a standalone HTML dashboard. The dashboard embeds its own chart data — no network calls, no build step.

Recommendation

Ship the reranker. Hold the pool width at 20 until the chunker fix lands, then re-measure — the p99 regression is almost certainly an artifact of fragmented tables inflating the candidate set with near-duplicates.

Why these controls

Toolbar rationale

You asked for “copy whole content” and “send to another app,” and for me to propose the rest. Every item earns its place against one test: does it shorten the loop between an agent writing a file and you doing something with it?

1Copy, four ways

One button, four payloads on the clipboard at once. Paste into a terminal and you get Markdown source; paste into Slack or Mail and you get formatted rich text. The system picks the right representation — you never choose wrong.

2Send to…

A real Open With list built from the apps actually installed on your machine, plus pinned targets. “Obsidian — Research vault” writes the file into the vault folder and then opens it, which sidesteps the URL-length limits that make obsidian:// links break on long documents.

3Diff since last write

The feature nothing else has. The app is already watching the file, so it keeps the previous version in memory. When an agent rewrites the document, changed blocks light up in the rendered view — you read the delta, not the whole thing again.

4Live badge

Green means the file on disk is being watched and the view is current. When a write lands, the view refreshes and holds your scroll position instead of throwing you back to the top.

5Blocked-request badge

Agent-written HTML gets rendered with the network switched off at the WebKit layer. The badge counts what was stopped and lets you allow it for that one document if you actually want the remote font or the live chart.

6Typography popover

Face, size, line measure, and light/dark. Same stylesheet drives the screen and the PDF, so what you tune here is what you export.

7Side tabs, hidden

⌘⇧E or a nudge at the left edge. Point it at a folder and it becomes a live list of every artifact in it, newest first, with a dot on anything written since you last looked.

8Outline & find

⌘F in-page find and a heading jump-list for long reports. Both live in the sidebar rather than the toolbar, so the chrome stays at eight items.

PDF themes

Six shipped, all extensible

A theme is a folder — a manifest, a screen stylesheet, and a print stylesheet. That means the reading view and the exported PDF are the same rendering path, and adding a theme requires no code. Licensing is settled: the iA Writer families and IBM Plex are OFL 1.1 and can be bundled outright; Charter, Palatino and SF Mono already ship with macOS, so they cost nothing.

What this study is not. These are static mock-ups built in a browser, not screenshots of a running app — the real thing renders through WebKit inside an AppKit window, and the reading faces here fall back to whatever your system has. The interaction model, control set, and typographic direction are the parts up for review. Timings, launch budget, and the architecture behind all of this are in the companion technical proposal.
